🔑 Logging in — what really happens

Unlike sign-up, login doesn't create a user — it finds the existing one and checks the password. Endpoint: POST /api/auth/login
① THE JSON BECOMES A LoginRequest DTO
📨 THE JSON YOU SENT
{
  "username": "asha",
  "password": "secret123"
}
➜
➜
🆕 LoginRequest OBJECT (1st object born)
LoginRequest {
  String username = "asha"
  String password = "secret123"
}
Only two fields (both @NotBlank). Jackson builds this DTO from the JSON before your method runs — the first object born.
② THE METHOD LINE — same input/output pattern
public ResponseEntity<AuthResponse> login(@Valid @RequestBody LoginRequest req)
OUTPUT = the AuthResponse it promises to return (born last) · INPUT = the LoginRequest it receives (born first)
🔎
STEP 1 — FIND THE USER
userService.findByUsername("asha")
Looks up the row in the database by username. Comes back as an Optional<User> — maybe a user, maybe nothing (if the username doesn't exist).
🔐
STEP 2 — CHECK THE PASSWORD
passwordEncoder.matches(typed, storedHash)
Hashes the typed password and compares it to the stored hash. The real password is never un-scrambled — it only compares fingerprints.
.filter(u -> passwordEncoder.matches(req.password(), u.getPasswordHash()))
// ✔ match → keep the user   ✗ no match → box becomes empty
🚫
STEP 3 — IF ANYTHING FAILED → 401
.orElseThrow(...) fires the error
If the username wasn't found OR the password was wrong, the box is empty, so this throws. Both cases give the same message — so an attacker can't tell which part was wrong.
✗ no user / wrong password → 401 Unauthorized "Invalid username or password"
🎟️
STEP 4 — PASSWORD OK → MAKE TOKENS, RETURN AuthResponse
Two tokens born, then 200 OK
Refresh token — refreshTokenService.create(...), random, saved to DB, rides in an HttpOnly cookie.
Access token (JWT) — made inside authResponse by jwtUtil.generateToken(), signed, short-lived, rides in the JSON body.
RefreshToken refresh = refreshTokenService.create(user.getUsername());
return authResponse(user, refresh, HttpStatus.OK);  // 200

🕐 The whole login, start to finish

1 POST /api/auth/login with { username, password } → Spring builds LoginRequest
2 findByUsername → is there a user?   then passwordEncoder.matches → right password?
3 either fails → 401 Unauthorized (same message), STOP
4 both ok → make RefreshToken + JWT access token
5 build AuthResponse → 200 OK + access in body + refresh in cookie
